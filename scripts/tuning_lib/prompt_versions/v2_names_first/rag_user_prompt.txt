## Task
Step 1. Before you write a requirement, list the names that you can use: at most 10. Go through the documentation and take each setting, command, endpoint, class or file that matters for this user story. For each name give: the name as the text of the documentation writes it, the number of its passage, and what the passage says about it, copied word for word (at most 25 words). If the passage only shows the name and does not describe it, write "no description".

Step 2. Write the security requirements that this user story needs.
- Use only names from your list, from the user story or from the system context.
- For a name with a description, you can state what the description says, and nothing more.
- For a name with "no description", you can say that it must be checked. Do not say what it does or what its default is.
- Where your list has no name for a point, write the requirement in general words. That is a correct answer.

Write as many requirements as the story needs, and not more.
