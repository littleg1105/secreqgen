## Example
This example is invented. It is about a greenhouse controller, and it shows only how to handle the documentation. Do not copy its content.

Documentation of the example:
[1] Vent control. The setting vent.max_open_percent limits how far the roof vents open. The default is 40.
[2] Heater settings: heater.safety_cutoff (a heading with no text)
[3] A single line of source code: PUMP_LOCK_TIMEOUT = 30

Three requirements and one unused line, in short form:
- Supported by passage [1]: "The controller shall reject a remote command that opens a vent beyond the value of vent.max_open_percent. The documentation gives 40 as its default." The passage says both things, so the requirement can say them.
- A name with no description, passage [2]: "The operator shall set heater.safety_cutoff, and the start-up check shall confirm that it is set." The passage only names the setting. So the requirement does not say what the setting does and gives no default.
- No passage: "The controller shall authenticate each remote command." No passage is about authentication, so the requirement is general and names no setting.
- PUMP_LOCK_TIMEOUT is only in a line of source code. The line does not say what it does, so no requirement uses it.
